# 红球集合预测改造（缺陷1 修复设计）

## 问题描述
数据 `Red1..Red6` 是开奖后**按大小排序**的。现有代码：
- `rf_model` / `lgbm_model` 对每列单独训练一个分类器（7 个模型）。
- `lstm_reds` 按 pos0..pos5 输出 6 个分布。
模型在学"最小值长什么样/最大值长什么样"的确定性排序规则，而非预测开奖集合，属伪相关。

## 目标
把红球预测改为**无序 6 元集合**预测：
- 模型输出 33 维概率（每个号码 1..33 在本期出现的 probability）。
- 取 top-6 作为预测集合。
- 评估时用"集合命中数"（预测6号 ∩ 真实6号 的交集大小），与随机基线（期望重叠 6*6/33≈1.09）对比。

## 实现方案

### A. 新模型 `SetRedModel`（建议新增，不动原 LSTM_REDS 以保留对照）
- 位置：`ml/models/set_model.py`
- 网络：LSTM/CNN 编码序列窗口 → 33 维 sigmoid（每个号码独立概率）。
- 标签：每期红球 6 个号码 one-hot（33 维，多标签）。
- 损失：BCEWithLogitsLoss（多标签二分类）。
- 预测：33 维 sigmoid → argsort 取 top-6。

### B. 评估指标（替代原 top-k 单标签）
- `set_hit(true_set, pred_set) = len(true ∩ pred)` 取值范围 0..6。
- 滚动外推时统计平均集合命中、命中≥1 / ≥3 / 全中 的频率。
- 与随机基线（重叠分布已知：超几何 C(6, k)C(27,6-k)/C(33,6)）对比。

### C. 输出格式
预测结果 CSV 增加列：模型、类型(red_set)、Top6号码、每号码概率、集合命中率基线。

## 验证
- 训练后在保留期（walk-forward 末段）统计平均集合命中，应≈随机基线 1.09，若显著更高则说明有信号（预期不会发生）。
