## 今日新发现 (3 条)

### 1. Lotto EV Toolkit (KrisRz) — 诚实的回测基座 + 期望值优化
- 类型: 集成方法 / 其他(工程基座)
- 来源: https://github.com/KrisRz/Ultimate-AI-Powered-Lottery-Prediction-System (GitHub, 2026, 自称 "Lotto EV Toolkit")
- 一句话可行性评估: 高潜力 —— 这是今日找到的唯一**自带 walk-forward 回测且明确宣称"任何方法都打不赢随机"**的工程仓库, 正好补齐我们管线"只出号、缺严格显著性检验"的短板; 其"期望优化"部分本质就是昨日的"避开热门组合"的工程化实现, 可一并吸收。
- 核心思路: ① 每个方法都跑 walk-forward 回测, 与**超几何分布无技巧基线**做 Monte-Carlo p-value + bootstrap 置信区间对比(我们现有 spectral 检验只验了"均匀性", 没做"方法 vs 随机"的胜率显著性, 这是直接可抄的能力); ② ROI 账本逐注记录并按真实开奖结算, dashboard 直接显示"亏了多少钱"; ③ 优化玩家**可控的两件事**: 选号热门度(避开生日号/连号等高拥挤组合以提升独中概率)与注数成本, 而非伪称预测号码。可接入点: 把它的 Monte-Carlo 显著性检验 + 超几何基线封装成我们 evaluate.py 的一个标准验收函数, 作为所有策略的及格线。

### 2. Ensemble Bayesian Model Averaging (EBMA) — 严谨的集成加权方法论(配 BayesBlend 包)
- 类型: 集成方法
- 来源: Montgomery, Hollenbach, Ward (2012) "Improving Predictions using Ensemble Bayesian Model Averaging", Political Analysis 20(3):271-291; 工具 https://ledger-investing-bayesblend.readthedocs-hosted.com (pip 可装 bayesblend, 提供 BMA / pseudo-BMA+ / stacking)
- 一句话可行性评估: 中-高潜力 —— 我们现有管线对 6 个模型是**等权均值集成**(`select_numbers.py` 各模型概率均值), 昨日"8专家"是启发式自适应权重; EBMA 给出了**有统计依据的、按验证期表现校准的后验权重**, 是这两者的更严谨替代, 且 pip 即有现成实现, 接入成本极低。
- 核心思路: 把 K 个模型的预测按后验模型概率加权平均, 权重由各模型在验证集上的 ELPD(期望对数预测密度, 用 PSIS-LOO 估计)经 softmax 归一化得到; pseudo-BMA+ 再用贝叶斯 bootstrap 计入估计不确定性, 避免小样本下权重过度自信。对我们最有价值的不是"它预测更准"(在随机过程上不会), 而是把"模型怎么融合"从拍脑袋变成可复现、可报告不确定度的标准流程 —— 这直接回应了 Rocky 对"统计严谨性"的要求。可接入点: 在 `select_numbers.py` 的集成环节用 bayesblend 替换等权均值, 权重随每期验证窗口滚动更新并落库。

### 3. 马尔可夫链预测的"有效性审计"方法论 — 对我们现有 markov_states 特征做 rigor 升级
- 类型: 数学模型
- 来源: https://developer.aliyun.com/article/264900 (阿里云开发者社区, 离散型马尔可夫链实现 + C# 代码) + 温海彬(2012)《马尔可夫链预测模型及一些应用》
- 一句话可行性评估: 中潜力 —— 马尔可夫"思路"我们已有(`config.markov_states=7`), 但原文给出的**马氏性 chi-square 检验 + C-K 方程多步转移 + 自相关系数滞时权重**三件套, 是我们特征工程里缺失的"该不该用、怎么用才不骗自己"的方法论, 值得补成一道前置校验。
- 核心思路: ① 用卡方统计量对序列做"马氏性检验"(α=0.05), 不通过则明确判定"用马尔可夫预测无意义"——这是对 SSQ 这种强随机序列应有的诚实闸门(大概率不通过, 正好用数据说话); ② 通过 C-K 方程(一步转移矩阵自乘 k 次)得到 k 步转移概率; ③ 用自相关系数 R(k) 算滞时权重 W(k), 对最近 K 期状态做加权预测。可接入点: 在 `feature_engineer.py` 的马尔可夫分支前加一步马氏性检验, 输出"是否通过"与 p-value, 不通过则自动降级该特征权重为 0, 防止对随机序列硬套马尔可夫产生虚假信心。

## 总体评估
今天 18 个 query / 5 轮检索的整体质量**偏低且高度重复**: 合法"新预测算法"几乎不存在, 空间被营销软文、玩具 repo 和关键词歧义结果填满——这与 08-13 的判断完全一致, 进一步坐实"彩票预测无银弹"。但今天仍有 3 条**真实增量**, 且都指向 Rocky 强调的方向(统计严谨性 + 工程可落地):
(1) Lotto EV Toolkit 补上了我们最缺的"方法 vs 随机基线"显著性检验与 ROI 实账, 应优先接入 evaluate.py;
(2) EBMA(BayesBlend)把等权/启发式集成升级为有后验权重的严谨融合, pip 即有, 接入成本极低;
(3) 马尔可夫马氏性检验给现有 markov 特征加一道诚实闸门。
下一步建议(按性价比排序): 先用 0.5-1 天把 Lotto EV Toolkit 的 Monte-Carlo 显著性检验 + 超几何基线封装进 evaluate.py 作为所有策略的验收线; 再花半天用 bayesblend 替换 select_numbers.py 的等权均值集成; 马尔可夫马氏性检验可作为 feature_engineer 的小补丁顺手做。三者都不承诺提升中奖率(数学上不可能), 但能显著增强系统的可信度与自检能力——这才是当前阶段真正值得投入的方向。
