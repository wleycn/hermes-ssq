# 双色球预测系统 (SSQ)

基于机器学习与深度学习的双色球彩票号码预测系统。通过分析历史开奖数据，使用多种模型（随机森林、LightGBM、LSTM、CNN、Transformer、CDM）预测下一期可能出现的号码及其概率，并将各模型概率集成后生成候选号码、通过邮件推送。

> 最后更新: 2026-08-22 | 维护人: Cheese (Hermes)

> ⚠️ 本系统仅供技术学习与研究，彩票中奖为随机事件，预测结果不构成任何投注建议。
>
> 🔬 **诚实结论（历史回测坐实）**：双色球为独立均匀随机过程，任何选号策略的期望收益 < 成本。wheel 30 注 ROI 历史回测 **-96.15%**（wheel_ledger 口径 B+C: 固定30注 vs 纯随机30注对截至 2026-08-14 的 3489 期核算; ML 策略 ROI 约 -75%）。本系统的价值是"统计严谨 + 诚实检验 + 自动化流程"，不是"能赚钱"。

### 推荐命中核对（reconcile_picks.py，2026-08-20 新增）

开奖信（22:00 cron）除报告开奖号外，自动把**该期推荐**逐组与开奖号比对，免去肉眼核对：

- **期号对齐（关键）**：开奖信核对的是 `predicted_picks WHERE period = 开奖期号 P`——即**上一期开奖后 22:15 发出的 P 期推荐**；当天 22:15 发的是 P+1 期推荐，**不参与**当晚核对。
- **比对内容**：A. 常规 5 组 + B. wheel 30 注，每组红球逐号标注 `✅`（命中，红色）/ `—`（未中，灰色），蓝球 `✅`/`—`，并给出结果（如"中3红+蓝 · 五等奖"）。
- **容错**：读 PG `predicted_picks` 只读；查不到当期推荐（上次发预测未成功）或 PG 异常时，开奖信降级为"无推荐记录/核对暂不可用"占位，**不影响开奖入库与发信**。
- **邮件格式**：开奖信整体为 HTML（`send_email(..., html=True)`），正文追加 `<hr>` + 核对块。

模块：`reconcile_picks.py`（`connect()` / `fetch_picks()` / `analyze_hits()` 纯函数 / `render_hits_html()` / `build_reconcile_block()`），单测 `_verify/test_reconcile.py`（20 例）。

## 模型说明

| 模型(规范名) | 类型 | 预测目标 | 核心算法 |
|------|------|---------|---------|
| RF (`rf`) | 传统 ML | 红球(33)/蓝球(16) | 随机森林分类（逐位置聚合为全量概率） |
| LightGBM (`lightgbm`) | 传统 ML | 红球(33)/蓝球(16) | LightGBM 梯度提升（同上聚合） |
| LSTM (`lstm`) | 深度学习 | 红球+蓝球联合 | LSTM 多任务学习（双头输出，窗口序列） |
| CNN (`cnn_reg`) | 深度学习 | 红球+蓝球联合 | CNN + 数学后处理（回归和值/奇偶比约束） |
| Transformer (`transformer`) | 深度学习 | 红球+蓝球联合 | Transformer 编码器（自注意力，窗口序列） |
| CDM (`cdm`) | 贝叶斯统计 | 红球+蓝球联合 | Compound-Dirichlet-Multinomial 后验均值（频数+先验平滑） |

### 多模型集成（select_numbers.py）

- **等权均值**（默认）：6 模型概率简单平均，向后兼容
- **EBMA**（`--ensemble ebma`）：按历史开奖 log-likelihood softmax 加权，默认 tau=8000（接近等权不坍缩，因随机过程上模型差异属噪声）
- **取数逻辑**：每模型每球种独立取最新 `run_at`（非单一全局最新），避免"必须一次跑完所有模型共享 run_at"的耦合
- **Conformal 风险分层**（默认开启，2026-08-19 C1 工程落地）：在集成概率基础上额外输出**带理论覆盖率保证的候选集**（如"以 90% 把握本期红球落在 20 个号码的集合内"）。校准用历史预测批次（PG `model_predictions`）对齐下一期真实开奖（1.csv），覆盖保证在 i.i.d. 下数学成立。**仅作可解释风险分层，不改变命中率**（命中率不可能被任何方法提升）。关闭：`--no-conformal`；调覆盖率：`--conformal-alpha 0.95`。

### 随机性探针套件（ml/probes/，2026-08-19 A 层工程落地）

定位：随机性检验器（非预测器），用正交统计方法反复检验"开奖序列是否真随机"。任一发现结构即推翻 i.i.d. 假设、可解锁新预测方向；当前全部 FLAT（无结构）。

| 探针 | 方法 | 实测结论（3492 期真实数据） |
|------|------|------------------------------|
| surrogate_probe | RS/AAFT/IAAFT 替代数据 + z 分数 | 9/9 检验 \|z\|<2 → RANDOM（干净，元验证金标准） |
| nist_probe | NIST SP 800-22 子集（频率/游程/串行） | 谨慎子集；naive 自然数编码在频率/游程/串行上误报 NONRANDOM（类别型序列需先白化），频谱已由 spectral.py 覆盖 |
| ordinal_probe | 排列熵 + Amigó χ² i.i.d. 检验 | 排列熵≈0.98（≈1）→ RANDOM；Amigó χ² 对单位置序列误报（边际非均匀，测错原假设），以排列熵为准 |
| transfer_entropy | 跨球位传递熵 + 50 置换 surrogate 显著性 | **INDEPENDENT，max_te≈0 → 实证支撑"逐球独立建模"假设（i.i.d.）**，关闭唯一开放缺口 |
| mfdfa_probe | 多重分形去趋势波动分析（广义 Hurst 谱） | 红 H(2)=0.473 / 蓝 0.493，Δh≈0，surrogate \|z\|<2 → RANDOM（无长程记忆、单分形） |
| rmt_probe | 随机矩阵理论特征值谱（33 号码 × 200 期窗口） | max_ratio z=-0.81 → RANDOM（无超越随机的跨号码联合结构；MP 上界为渐近理论，以 surrogate 相对判据为准） |
| calibration_probe | 概率校准诊断（Brier / ECE / isotonic） | 均匀输出 ECE≈0.007、isotonic≈0 → 校准在 i.i.d. 下无操作空间（仅监控，不进选号） |

> ⚠️ **方法论诚实声明**：NIST / ordinal-χ² 的"NONRANDOM"是**编码/原假设误设导致的伪阳性**，不是真结构。它们揭示的真实边界是——类别型彩票序列（自然数 1..33）不能直接套用于为均匀比特流设计的检验。NIST 进生产性价比低，仅留作方法论参考。

### 不确定性量化（ml/conformal/，2026-08-19 C 层工程落地）

- **conformal_predict.py**：Conformal Prediction 集合层（Angelopoulos & Bates 2021）。把集成概率升级为带理论边际覆盖率保证（1-α）的候选集。已验证：蓝 0.897≈0.90 目标（合成数据）。生产已接入 `select_numbers.py`。
- **edl_probe.py**：Evidential Deep Learning 区分度先验实验。**实证结论**：证据量在 i.i.d. 下退化至常数（auroc=0.5），证实 qwen3.8-max 三日审核的担忧——**仅作解释层，不进生产选号逻辑**。

### 混沌 / 相空间重构检验（ml/spectral_chaos.py）

Takens 延迟嵌入 + Rosenstein Lyapunov + FFT 相位随机化替代检验 + 样本熵：
- **定位**：随机性检验器（非预测器），延续光谱探针的"检验优先"思路
- **实测结论**：SSQ 开奖序列无混沌结构（Lyapunov z=0.29, p=0.78，打乱排序后）
- **重要陷阱（已记录）**：开奖号按升序排列（Red1<...<Red6）拍平后会引入**排序伪影**——未打乱时 Lyapunov 误报 CHAOTIC（z=9.88），每期内打乱后回到 RANDOM。**任何序列化开奖数据做时序分析前必须先打破排序**
- **样本熵 FFT 分支有已知假阳性**（纯随机整数序列误报 CHAOTIC z=50.7），需以 Lyapunov 分支为准

### 马尔可夫马氏性闸门（feature_engineer.py）

新增卡方列联表马氏性检验（α=0.05）：
- 实测奇偶比序列 p=0.7494 >> 0.05，不通过
- 闸门意义：在随机序列上，马尔可夫预测无意义，下游自动 markov_valid=False

### 旋转矩阵覆盖设计（wheel.py）

贪心 4-子集覆盖算法：
- 池大小 N（默认 18），目标：30 注内让尽可能多的 6-子集"至少 4 红命中"
- N=18 时 pass_rate=95.42%（穷举精确计算 C(18,6)=18564 种）
- **诚实事实**：覆盖率只依赖池大小，与具体哪 18 个球无关。ML Top-18 池与随机 18 球池期望等价（历史回测验证：ML ROI -75.43% vs 随机中位数 -75.87%，差异 < 1 标准差）

### 模型加速（实测）

LSTM 在 CPU 上原训练极慢（lstm 窗口 330 + 256 epoch ≈ 22 分钟）。已调优：

- `lstm` 窗口 `330 → 128`
- 全局 `epochs 256 → 80`（早停 patience=7）
- 训练循环加进度打印（消除"像卡死"误判）

加速后：lstm 单模型训练 **~59s**，transformer 约 9 分钟（6 模型含 transformer/cdm 批量入库约 10 分钟）。

Transformer 性能优化（2026-08-15）：注意力 O(n²)，初始 window=128 + 每 epoch 验证导致 **32 分钟**。已调优：

- `window_size 128 → 32`（注意力计算省 16 倍）
- `batch_size 64 → 128`、`val_frequency 5 → 10`（对齐 LSTM）
- `dim_feedforward 256 → 128`（对齐模型内部默认）

调优后：**32 分钟 → 9 分钟**（3.6 倍）。随后发现真正瓶颈并非注意力/维度，而是 **CPU 线程数**：PyTorch 默认 8 线程跑 64 维小张量时，线程调度开销吞掉计算收益（单 Linear 8 线程 12.6ms vs 4 线程 0.19ms，慢 66 倍）。`TransformerAllModel.train()` 内显式 `torch.set_num_threads(4)` 后，实测单模型重训 **32 分钟 → 29 秒（18.8 倍）**，6 模型批量约 10 分钟内完成。4 线程为本机最优（实测 1/2/4/8 线程对比）。

⚠️ **2026-08-15 多agent独立验收修正（重要）**：早先结论"仅 transformer 需要、LSTM/CNN 免疫"是**错的**——测量被 `torch.set_num_threads` 的**进程级全局性**污染（在 transformer train() 内设置后，同进程内 LSTM/CNN 测量也变成 4 线程）。独立 test 子代理在干净进程逐模型扫描实测：**所有 torch 模型在 8 线程下都崩溃级慢**——LSTM +8818%、CNN +2860%、Transformer +591%（8 vs 4 线程）。已修复：`batch_predict_pg.py` **入口统一 `torch.set_num_threads(4)`**（不能在模型内部设，MODELS 里 LSTM/CNN 排在 transformer 前面，会先用 8 线程跑完）。

⚠️ 性能教训：CPU 上小模型训练务必实测线程数，默认 8 线程对 64 维小张量是灾难；且 `set_num_threads` 是全局的，任何"某模型免疫"的结论必须在新进程、干净环境验证。

⚠️ 配置注意：`ml/config.py` 的 `TRANSFORMER_CONFIG` 是唯一生效配置，`ml/main.py` 实例化时显式传入；`transformer_model.py` 模块内默认值仅作 fallback。

### CNN (cnn_reg) 后处理流程

CNN 数学增强模型在神经网络输出后，依次执行 4 步数学约束：

1. **信息熵检查**：检测预测是否处于高混乱状态，若是则做平滑处理
2. **正态分布过滤**：预测和值超出 μ±2.58σ 时替换极端号码
3. **泊松分布优化**：根据泊松概率调整号码选择
4. **和值约束**：用回归预测的 Next_Sum 校正最终和值

## 专业术语通俗解释

> 项目里堆了很多统计/ML 黑话，下面用大白话翻译。核心一句话：**双色球开奖是独立均匀随机，任何方法都改不了"中奖概率"这个物理下限；本系统所有高级算法都只做两件事——①检验随机性是否真的干净，②把"概率"翻译成人话（风险分层）。**

### 基础概念（先搞懂"这套系统在干嘛"）

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **双色球 (SSQ)** | 中国福利彩票：每期从 1–33 **不重复**选 6 个红球 + 从 1–16 选 1 个蓝球。一等奖要 6+1 全中，组合数是 C(33,6)×16 ≈ **1772 万**，所以一等奖概率 ≈ 1/1772 万（相当于连续抛 24 次硬币全正面）。二等奖 6+0 也极难，三/四/五/六等奖门槛递减。本系统**不承诺中奖**，只研究"能否比纯随机略好一点"——结论是：不能。 |
| **预测 / 回测 / 训练** | 三个不同阶段：①**训练**=用历史数据让模型学规律（调参数）；②**预测**=用训好的模型算下期概率；③**回测**=假装回到过去，用当时的模型预测当时未知的开奖，检验"如果当年这么买，能赚吗"。回测才是检验方法有没有用的试金石，不是看训练时多准。 |
| **1.csv** | 历史开奖数据表（3492 期，每行一期）。**生产系统的唯一权威数据源**——所有模型、检验都读它，永远以它为准。类比：这是"原始账本"，后续所有分析都是它的副本或加工。 |
| **draw_history** | 1.csv 在 PostgreSQL 里的**镜像备份**。**只读归档**，默认不自动同步（手动跑 `pg_schema.py` 才更新），所以可能比 1.csv 旧。设计上故意如此（见 H1 决策）——防止自动同步把脏数据写进归档。 |
| **model_predictions** | 6 个模型对每个号码"觉得多可能中奖"的概率表，存 PG。每模型每球种（红33/蓝16）独立记最新一批（用 `run_at` 时间戳区分）。类比：6 个评委各给 33 个红球 + 16 个蓝球打分，打分表就在这里。 |
| **predicted_picks** | 集成概率后**实际选出的号码**落库表（top5 组 + wheel 30 注），带期号、流行度、seed，用于日后复盘"当初选了啥、中没中"。 |
| **run_at / data_date** | `run_at`=模型跑出的时间戳（精确到秒，区分不同批次）；`data_date`=北京日期（哪一期）。预测在开奖日前生成，预测的是"下一期"——所以 `data_date` 永远领先实际开奖日。 |
| **i.i.d. (独立同分布)** | Independent and Identically Distributed = "每期开奖互不影响、且都服从同一套随机规律"。本系统所有随机性检验的**原假设**（默认假定）：目前**未被推翻**。这是整条科学立场的基石——如果开奖不 i.i.d.，才可能出现可预测结构。 |
| **原假设 / 备择假设** | 统计检验的两种立场：原假设 H0="没结构、纯随机"；备择假设 H1="有结构、可预测"。检验是"试着推翻 H0"，推不翻就**保留 H0**（即认了随机）。本系统所有探针都是在试推翻 H0，结果都推不翻。 |
| **FLAT** | 检验结果术语：没找到任何可预测结构（"平"的，曲线是平的）。**这是科学结论，不是失败**——它说明"随机假设成立"，恰恰是诚实研究的成果。 |
| **ROI** | Return on Investment 投资回报率 =（赚 − 花）/ 花。本系统回测 ROI ≈ **-75%**，即每花 1 元买注平均亏 0.75 元——长期必亏。wheel 30 注口径 B+C 回测更惨（-96%）。这数字用来"劝退幻想"，不是吓人。 |
| **蒙特卡洛 (Monte Carlo)** | 一种"用大量随机模拟代替精确计算"的方法。本项目用它造"纯随机买注"的基线——跑 1000 次随机选号回测，看随机策略本身能赚多少（答案：也是亏），用来对比 ML 策略有没有真优势。 |
| **基线 (baseline)** | 衡量"你的方法有没有用"的参照物。彩票里基线就是"纯随机买"或"机选"。任何 ML 策略必须**显著胜过基线**才算有效——本系统 ML 策略没有，所以结论是 FLAT。 |

### 模型与算法（"6 个评委怎么想的"）

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **模型 (model)** | 一个"从输入特征算出输出概率"的数学函数。本项目 6 个模型是 6 种不同思路的评委，各有偏好，集成后取平均更稳。 |
| **RF / 随机森林** | 让很多棵"决策树"（层层问"这个数大于 X 吗？"的二叉判断）各自投票，再多数决。传统 ML 代表。**它怎么想**：把历史号码切成一小块一小块规律，但彩票没规律可切，所以它在学噪声。本系统对红球**逐位置**（Red1…Red6 + Blue1）各训一棵，共 7 个子模型。 |
| **LGBM / LightGBM** | 梯度提升树：一棵树不够，就"先训一棵，看错在哪，再训下一棵专门补错"，迭代变强。比随机森林更快更准的传统 ML。同样逐位置建模。 |
| **LSTM** | "长短期记忆"神经网络，一种能"记前情"的循环网络，适合时间序列（把过去 N 期当上下文）。本项目把它合并为**唯一双头入口**（`LSTMModel`），一次输出红+蓝 49 维概率。类比：它像边读边记笔记的读者，但彩票每期独立，笔记帮不上忙。 |
| **CNN** | 卷积神经网络，擅长找"局部相邻模式"（如图像里一小块纹理）。本项目 `cnn_reg` 在神经网络输出后加**数学后处理**（回归约束和值/奇偶比），让它别输出太离谱的组合。 |
| **Transformer** | 用"自注意力"让序列里任意两个位置直接对话、抓长程关系（ChatGPT 同款底层思路）。本项目用滑动窗口把历史开奖切成序列喂它。对彩票而言长程关系≈0，但它架构干净、可复用。 |
| **CDM** | Compound-Dirichlet-Multinomial，贝叶斯统计方法：用"历史出现频率 + 平滑先验"估每个号码的概率。本质就是"数每个号历史上出了几次，再加一点平滑防 0"。最朴素也最稳的基线型模型。 |
| **EBMA** | 贝叶斯模型平均的一种：按各模型历史表现加权融合（谁准谁权重高）。实测在随机过程上权重会**坍缩回等权**（因为模型差异主要是噪声，没有谁真更准），故默认用**等权均值**。这是个"聪明想法被现实打脸"的例子。 |
| **等权均值** | 6 个模型概率直接取算术平均。最稳健的融合方式——既不放大某个模型的噪声，也不依赖"谁更准"这个在随机数据上无法成立的判断。本系统默认集成方式。 |
| **softmax 温度 (τ)** | 控制"概率分布尖锐还是平缓"的旋钮。τ 大→接近均匀（大家差不多，等于没偏好）；τ 小→把微小差异放大成"非它不可"。在随机数据上用小 τ 等于**把噪声当信号**，危险。 |
| **双头输出** | 一个模型同时输出"红球概率"和"蓝球概率"两个头（而非两个独立模型）。本项目 LSTM/CNN/Transformer/CDM 都是双头；RF/LightGBM 因历史设计是逐位置，靠聚合拼回全量。 |
| **分类 vs 回归** | 两种学习目标：分类="这是 A 类还是 B 类"（如"这个位置出不出 7 号"）；回归="预测一个连续数值"（如"下期和值是多少"）。`cnn_reg` 的"reg"就来自它用回归去约束和值/奇偶比。 |
| **损失函数 (loss)** | 衡量"模型猜得有多离谱"的分数，训练就是不断调参数让 loss 变小。彩票里 loss 能降到很低（训练集），但那是**记住噪声**，不是学到规律。 |
| **过拟合 (overfitting)** | 模型把训练数据的噪声当规律背下来，训练时满分、遇到新数据就懵。彩票极易过拟合（数据少、噪声大），所以本项目不追求训练精度，而用回测 + 随机性检验来防自欺。 |
| **超参数 (hyperparameter)** | 模型"出厂设置"（如树的数量、网络层数、窗口大小），训练前定好、不参与学习。调超参是体力活，但彩票上再怎么调也突破不了随机下限。 |
| **训练 / 推理 (inference)** | 训练=喂历史数据调参数（费时，月度跑一次）；推理=用训好的模型算新概率（快，开奖日跑）。本系统默认推理复用已存模型，不每次重训。 |

### 特征与统计（"喂给模型的原材料"）

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **特征工程** | 从原始开奖号里"算"出额外信息（频率、遗漏、冷热、跨度、和值等），作为模型输入。类比：不只给模型看"上次开了 3 5 8"，还告诉它"3 号已经 20 期没出（冷）""这期和值 120"。问题是——这些衍生信息在 i.i.d. 下**不含新信号**，所以加了也白加。 |
| **特征 / 标签 / 样本** | 机器学习三件套：**样本**=一条历史数据（某一期）；**特征**=输入（算出来的各种指标）；**标签**=想预测的答案（下期实际开奖）。训练 = 看很多"特征→标签"对，学映射。 |
| **冷热号** | 热号=近期常出；冷号=很久没出。民间迷信"冷号该出了"或"热号会继续"。本系统已实测**关闭该特征**（无预测增益，纯噪声）。 |
| **遗漏 (omission)** | 某个号码连续多少期没出现。遗漏大≠快出了（i.i.d. 下每期概率不变），但常被误读为"该补了"。 |
| **跨度 / 和值** | 跨度=红球最大减最小（描述号码铺多开）；和值=6 个红球相加（描述整体大小）。都是描述号码"形状"的指标，用来让选号别太畸形（如全 1–6 或全 28–33）。 |
| **马尔可夫链** | "下一期只取决于上一期、与更早无关"的模型。本系统已用卡方检验**证伪**（开奖不满足马氏性——过去不只上一期有影响，且影响本身也是噪声）。 |
| **信息熵 / 排列熵** | 衡量序列"有多乱"。熵越大越随机；排列熵≈1（最大乱度）= 接近纯随机。本系统 ordinal 探针测出排列熵≈0.98 → **支持随机**。注意：普通"熵"要用对方法，错的方法会误报。 |
| **泊松过程** | 描述"随机事件按时间发生频率"的数学模型（如单位时间内中奖人数）。用来建模"某号平均每多少期出一次"，但彩票每期独立，泊松只是描述频率、不预测具体哪期。 |
| **卡方检验 (χ²)** | 统计里判断"观察值分布是否符合预期分布"的方法（算观察与理论的偏差平方和）。本系统用它检验马尔可夫性、频数均匀性等，结果都不显著→随机。 |
| **p 值 (p-value)** | 在原假设成立时，看到"当前这么极端或更极端结果"的概率。p 小（如 <0.05）= 原假设下很难出现，可怀疑 H0；p 大 = 数据与随机一致，**不能证随机，只能说没推翻**。本系统探针 p 都偏大 → 保留随机假设。⚠️ p 值不是"随机的概率"，别误读。 |
| **标准差 / 方差** | 衡量数据"抖不抖"。方差大=数值散；标准差=方差开根号，单位同原数据。用来描述模型概率的波动、回测收益的起伏。 |
| **归一化 / 标准化** | 把不同量纲的特征拉到同一尺度（如都变到 0–1 或均值 0、标准差 1），防止"和值几千"压制"遗漏几十"。本系统 `StandardScaler` 做标准化。 |
| **相关性** | 两个量"同涨同跌"的程度（-1 到 1）。本系统测各球位间传递熵≈0，相当于相关性≈0 → 球位间独立。 |
| **滑动窗口 (sliding window)** | 取"连续 N 期"作为一个样本（如窗口 33 期），窗口一步步往后挪生成很多样本。LSTM/Transformer 用这个把开奖变成序列训练数据。 |
| **时间序列** | 按时间顺序排列的数据。开奖号天然是时间序列，所以序列模型（LSTM/Transformer）看着对口——但 i.i.d. 下"顺序"本身不携带可预测信息。 |

### 随机性检验（探针）——"专门挑刺的裁判"

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **探针 (probe)** | 一个"检验器"，专门测试开奖序列是否真随机。**不预测号码，只挑刺**——它的存在是为了防止我们自欺"模型学到了规律"。本系统 A 层就是这套。 |
| **替代数据 (surrogate)** | 把真实序列打乱 / 相位随机化，造出"该随机却随机"的假数据，看真数据是否比假数据更"有结构"。**随机性检验的金标准**——若真数据并不比 surrogate 更特殊，就是随机。本系统 surrogate 探针结论：RANDOM（所有 \|z\|<2）。 |
| **NIST SP 800-22** | 美国国家标准局给密码学比特流用的随机性测试套件（频率、游程、串行等）。本系统只取**谨慎子集**——因为彩票自然数是 1–33，直接转比特会有"位边际不平衡"伪影导致误报，需先白化。 |
| **伪影 (artifact)** | 不是真实信号、而是"测量/编码方式自己造出来的假结构"。如自然数 1–33 转二进制，低位比特天生不平衡，会让 NIST 误以为"不随机"。本系统实测 NIST "NONRANDOM" 就是这种伪影，不是真发现。 |
| **传递熵 (Transfer Entropy)** | 衡量"球 A 的变化能否预测球 B"。本系统测出≈0 → 证明**各球位相互独立**（逐球独立建模是对的）。这是本项目最关键的实证结论之一（A4）。 |
| **相空间重构 / Lyapunov** | 混沌理论工具：把一维序列"展开"成多维轨迹，看是否有混沌吸引子、最大 Lyapunov 指数是否 >0（有混沌）。实测无混沌（排序伪影已排除）。 |
| **白化 (whitening)** | 把相关性/偏差去掉，让数据变成标准随机（均值 0、协方差单位阵）。NIST 测彩票前需要先白化自然数编码，否则伪影干扰。 |
| **功效 (power)** | 检验"真有结构时能发现它"的能力。样本少→功效低→即使有结构也可能测不出（FLAT 可能是"没测出来"而非"真没有"）。本系统 3492 期对多数检验够用，但对某些 NIST 子项仍偏少，结论带这个 caveat。 |

### 不确定性量化（UQ）——"不但给答案，还告诉你答案多不靠谱"

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **UQ (Uncertainty Quantification)** | 不确定性量化：不只给一个答案，还告诉你"这个答案有多不靠谱"。彩票预测本身不可靠，UQ 把"不可靠"说清楚，而不是假装精确。 |
| **Conformal Prediction (保角预测)** | 一种数学方法：给出"以 90% 把握，真实答案落在这个集合里"的候选集。**保证的是集合覆盖概率，不是命中概率**——本系统用它把"概率 0.03"翻译成"红球有 90% 把握在这 20 个号里"，纯解释层（不改选号）。覆盖率保证在 i.i.d. 下数学成立。 |
| **边际覆盖率 (marginal coverage)** | 长期来看，集合包含真实开奖号的比例 ≥ 1-α（如 90%）。注意是"集合够大能罩住"，不是"集合里哪个会中"。 |
| **校准 (calibration)** | 模型说"概率 0.3"的事，真实是否真发生 30%？校准好=说的中；校准差=嘴上说一套实际另一套。Conformal 用历史批次做校准，本系统校准样本少（<30 期）时诚实标注噪声。 |
| **先验 / 后验 (贝叶斯)** | 贝叶斯思路：先验=出手前的旧观念（如"每个号差不多"）；后验=看了数据后的新观念（频率 + 先验平滑）。CDM 就是"先验平滑 + 历史频率 → 后验概率"。先验防止"某号没出过就估成 0"。 |
| **EDL (Evidential Deep Learning)** | 让模型额外输出"我对自己答案有多确信"的证据值（像附赠一个置信度）。本系统实测证据在随机数据上**退化成常数** → 区分不了什么，仅留作解释层，不进生产。 |
| **auroc=0.5** | 区分度指标（曲线下面积）：1=完美区分，0.5=完全瞎猜（抛硬币）。EDL 在此值说明它区分不了什么。 |
| **证据 (evidence)** | EDL 里的"确信度"数值。随机数据上证据≈常数 → 模型对谁都没把握，符合预期（彩票确实没法有把握）。 |

### 工程与调度（"机器怎么自动跑起来"）

| 术语 | 大白话（含机制与为什么重要） |
|------|--------|
| **cron** | 定时任务调度器（类似手机闹钟）。本项目三个 cron：抓开奖（开奖日 22:00）、发预测（22:15）、月度重训（每月 1 号 03:00），全自动无需人工。 |
| **H1 决策** | 架构铁律之一：draw_history 是只读归档，PG 不同步开奖数据，手动跑 `pg_schema.py` 才更新。防止自动链路把脏数据写进权威归档。 |
| **wheel / 旋转矩阵** | 一种"用更少注数覆盖更多组合"的数学设计（贪心 4-子集覆盖），提高"至少中 4 红"的概率。回测 ROI 仍 -96%——**数学上优化了覆盖，但挡不住随机必亏**。 |
| **幂等 (idempotent)** | 同一个操作跑多次结果一样、不重复副作用。本项目数据入库用 `ON CONFLICT ... DO UPDATE` 实现幂等：重跑不会插出重复行，只更新。 |
| **落库 / upsert** | 落库=把结果写进数据库；upsert=update-or-insert（有就更新、没有就插入），幂等保障的核心操作。 |
| **pytest** | Python 测试框架。本项目 `_verify/` 下有探针与 conformal 的单元测试，保障改动不破坏既有功能（改完跑一遍，红=坏了，绿=没事）。 |
| **回归测试 (regression test)** | 改完代码跑旧测试，确认"没把以前好的地方改坏"。本系统每次大改（如模型收敛）都跑全量 pytest。 |
| **PG / PostgreSQL** | 开源关系数据库（表格式存储），存预测概率、开奖归档、选号复盘。比 csv 适合多批次查询。 |
| **虚拟环境 (venv)** | 项目专属的 Python 隔离空间（`.venv/`），装依赖不影响系统其他项目，保证"在我机器上能跑"在你机器也能跑。 |
| **管线 / 管道 (pipeline)** | 一串自动衔接的步骤（抓数据→训练→预测→集成→选号→发信），像工厂流水线。本系统就是一条 SSQ 管线。 |
| **1-indexed** | 号码从 1 开始数（红球 1–33，蓝球 1–16），不是程序员习惯的 0 开始。代码里处处注意"返回的是 1-indexed 就不用再 +1"，避免 off-by-one bug。 |
